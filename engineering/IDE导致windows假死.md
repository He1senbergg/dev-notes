**问题现象**：开发时电脑突然完全卡死（冻结）几分钟，甚至提示“内存不足”，但看任务管理器物理内存可能才用了 70% 左右。
**根本原因**：同时开启多个重型 IDE（如 CLion、IntelliJ IDEA、GoLand），它们会向系统**预申请（Commit）极其恐怖的虚拟内存额度**。当累计申请量超过 Windows 当前的“已提交（Committed）”天花板时，系统就会因为内存调度死锁而陷入长达数分钟的严重卡死。

---

## 💡 核心修复方案：手动扩容 Windows 虚拟内存上限

对于 **32GB 物理内存**的开发机，无需升级硬件，只需把虚拟内存的天花板拉高，让多个 IDE 有地方“挂账”即可。

### ⚙️ 最佳参数配置（针对 32GB 内存机器）

* **初始大小 (Initial size)**：`16384` （即 16 GB）
* **最大值 (Maximum size)**：`49152` （即 48 GB）

> **为什么这么设？**
> 这样配置后，你的系统总提交上限将达到 `32G (物理) + 48G (虚拟) = 80GB`，完全喂饱三大 IDE。且日常状态下 Windows 会动态管理，不占用过多硬盘空间。

---

## 🏃‍♂️ 具体操作步骤

1. **打开系统属性**
   按下 `Win + R` 键打开运行窗口，输入 `sysdm.cpl` 并回车。
2. **进入虚拟内存设置**
   在弹出的窗口中依次点击：**高级** 选项卡 -> 性能栏的 **设置** -> 性能选项窗口中的 **高级** 选项卡 -> 虚拟内存栏的 **更改**。
3. **配置自定义大小**
   
   * 取消勾选最上方的 *“自动管理所有驱动器的分页文件大小”*。
   * 选中 **C 盘**（或速度最快的固态硬盘 SSD）。
   * 点选 **自定义大小**，在输入框中分别填入：
     * 初始大小 (MB)：`16384`
     * 最大值 (MB)：`49152`
4. **【关键】锁定设置并重启**
   输入完数值后，**必须先点击输入框下方的 “设置 (Set)” 按钮！**（*这一步最容易漏，不点直接点确定会导致设置失效*）。
   确认上方驱动器列表里的数字更新为 `16384 - 49152` 后，再一路由“确定”点出去，并**立即重启电脑**。

---

## 📌 日常验证小贴士

重启后，可以打开 **任务管理器 -> 性能 -> 内存**，盯住右下角的 **“已提交 (Committed)”** 指标（日常状态下大概显示为 `13/47.7 GB` 左右）。只要右边的总上限天花板被安全拉高，以后全家桶开得再多，系统也绝对不会再产生几分钟的窒息卡死了。
